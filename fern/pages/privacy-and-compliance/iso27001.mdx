## Overview

ISO 27001 asks you to manage the security risk of every system and supplier inside the scope of your information security management system (ISMS). A feature flag platform decides what runs in production, so auditors expect it to support your access and change controls. This page shows which [Unleash Enterprise](https://www.getunleash.io/pricing) features map to which Annex A controls, and how we secure the hosted service.

## Unleash features mapped to ISO 27001 controls

<StickyTable>
| ISO27001 Control | Control Description | Unleash Feature |
|------------------|---------------------|-----------------|
| 5.2 Information security roles and responsibilities | Information security roles and responsibilities should be defined and allocated according to the organization's needs. | Unleash provides granular [role-based access control](/concepts/rbac) (RBAC) and [approval workflows](/concepts/change-requests) for state changes. |
| 5.3 Segregation of duties | Conflicting duties and conflicting areas of responsibility should be segregated. | [Change requests](/concepts/change-requests) add an approval step, so the person who requests a flag change in a protected environment isn't the one who approves it. Users with the Admin root role can approve their own changes, and the skip change requests permission bypasses the approval step, so limit both to keep duties segregated. |
| 5.15 Access control | Rules to control physical and logical access to information and other associated assets should be established and implemented based on business and information security requirements. | In addition to RBAC, Unleash supports [single sign-on](/concepts/sso) (SSO) authentication and [SCIM integration](/concepts/scim) for user account provisioning. |
| 5.16 Identity management | The full life cycle of identities should be managed. | Unleash supports SSO and SCIM integration for automatic user account provisioning. |
| 5.18 Access rights | Access rights to information and other associated assets should be provisioned, reviewed, modified, and removed in accordance with the organization's topic-specific policy and rules for access control. | Unleash supports SSO and SCIM integration for automatic user account provisioning. |
| 8.2 Privileged access rights | The allocation and use of privileged access rights should be restricted and managed. | Unleash provides RBAC, granular permission administration, custom root roles, as well as approval workflows for state changes. |
| 8.3 Information access restriction | Access to information and other associated assets should be restricted in accordance with the established topic-specific policy on access control. | Unleash provides RBAC, granular permission administration, [custom root roles](/concepts/rbac#custom-root-roles), as well as [approval workflows](/concepts/change-requests) for state changes. |
| 8.5 Secure authentication | Secure authentication technologies and procedures should be implemented based on information access restrictions and the topic-specific policy on access control. | In addition to RBAC, Unleash supports SSO authentication setup and SCIM integration. |
| 8.6 Capacity management | The use of resources should be monitored and adjusted in line with current and expected capacity requirements. | Unleash provides both traffic monitoring and configuration statistics to help system administrators monitor and adjust resource usage. |
| 8.8 Management of technical vulnerabilities | Information about technical vulnerabilities of information systems in use should be obtained, the organization's exposure to such vulnerabilities should be evaluated, and appropriate measures should be taken. | [Kill switches](https://www.getunleash.io/feature-flag-use-cases-software-kill-switches) turn off an affected feature in production within seconds, which limits exposure while a fix is prepared. |
| 8.9 Configuration management | Configurations, including security configurations, of hardware, software, services and networks should be established, documented, implemented, monitored and reviewed. | Flag configuration lives in one central system. Each flag records who created it and belongs to a [project](/concepts/projects) with a defined owner, and the [event log](/concepts/events#event-log) keeps its full change history. The [import and export](/concepts/import-export) API lets you export configuration for review or backup. |
| 8.13 Information backup | Backup copies of information, software, and systems should be maintained and regularly tested in accordance with the agreed topic-specific policy on backup. | When self-hosting Unleash, the product provides an API to export its configuration, facilitating the backup automation. |
| 8.15 Logging | Logs that record activities, exceptions, faults, and other relevant events should be produced, stored, protected, and analyzed. | Unleash records every change in the [event log](/concepts/events#event-log) and every sign-in in [login history](/concepts/login-history). |
| 8.25 Secure development life cycle | Rules for the secure development of software and systems should be established and applied. | [Release templates](/concepts/release-templates) and progressive rollouts make staged exposure a defined, repeatable part of every release. |
| 8.31 Separation of development, test and production environments | Development, testing and production environments should be separated and secured. | Each [environment](/concepts/environments) has its own flag state, [API tokens](/concepts/api-tokens-and-client-keys) and permissions. Change requests can be required per environment. |
| 8.32 Change management | Changes to information processing facilities and information systems should be subject to change management procedures. | [Change requests](/concepts/change-requests) put an approval gate in front of production flag changes. The [ServiceNow integration](/integrate/servicenow) syncs each change request to your change records. |

## How we secure the hosted service

If you use the hosted version of Unleash, the rows below describe how we run the service. They count as supplier evidence for your own supplier controls (5.19 to 5.22). Our SOC 2 Type II report and penetration test results are available on request through the Trust Center.

<StickyTable>
| ISO27001 Control | Control Description | Unleash Feature |
|------------------|---------------------|-----------------|
| 5.7 Threat intelligence | Information relating to information security threats should be collected and analyzed to produce threat intelligence. | When using the hosted version of Unleash, [Amazon GuardDuty](https://aws.amazon.com/guardduty/) continuously analyzes your instance for threats and alerts Unleash to any risk. |
| 5.33 Protection of records | Records should be protected from loss, destruction, falsification, unauthorized access, and unauthorized release. | When using the hosted version of Unleash, your data records are protected with a resilient architecture leveraging AWS data redundancy and backup services. This is described in our annual SOC2 report available in the Trust Center. |
| 5.35 Independent review of information security | The organization's approach to managing information security and its implementation including people, processes, and technologies should be reviewed independently at planned intervals, or when significant changes occur. | An independent third party runs Unleash's annual penetration test, and an external auditor issues our SOC 2 Type II report. Both are available on request through the Trust Center. |
| 5.37 Documented operating procedures | Operating procedures for information processing facilities should be documented and made available to personnel who need them. | Unleash follows 14 internal policies to ensure secure information processing as part of its SOC2 compliance. |
| 8.8 Management of technical vulnerabilities | Information about technical vulnerabilities of information systems in use should be obtained, the organization's exposure to such vulnerabilities should be evaluated, and appropriate measures should be taken. | [Amazon Inspector](https://aws.amazon.com/inspector/) continuously scans the hosted service for software vulnerabilities, and Unleash applies patches as needed. |
| 8.13 Information backup | Backup copies of information, software, and systems should be maintained and regularly tested in accordance with the agreed topic-specific policy on backup. | In the hosted version of Unleash, periodic backups are automated. |
| 8.14 Redundancy of information processing facilities | Information processing facilities should be implemented with redundancy sufficient to meet availability requirements. | The hosted version of Unleash is a highly available platform with load balancing, and redundancy across multiple AWS availability zones. |
| 8.16 Monitoring activities | Networks, systems, and applications should be monitored for anomalous behavior, and appropriate actions taken to evaluate potential information security incidents. | The hosted version of Unleash provides network and application monitoring, intrusion detection, and diverse utilization alerts supported by an SRE team and a structured incident handling process. |
</StickyTable>

Your Unleash [plan](#plans) and [version](#versioning) determine what features you have access to. Our documentation displays the availability for each feature using the following annotation:

<Button small outlined className="version-button" href="/support/availability">v5.7</Button><Button small href="https://www.getunleash.io/plans" className="cta-button">Enterprise</Button>

This is an example of a feature that is only available to Enterprise customers who are on version `5.7` or later.

## Plans

- [Open Source](https://www.getunleash.io/pricing) - Available on [GitHub](https://github.com/Unleash/unleash). Source code is licensed under AGPLv3 from v8.0.0 onwards, and under Apache 2.0 in earlier versions. Official Docker images are licensed under Apache 2.0.
- [Enterprise](https://www.getunleash.io/pricing) - Available as pay-as-you-go or as an annual contract, either as cloud-hosted or self-hosted.
- Pro - Currently not offered.

## Unleash Edge

- Open Source - Deprecated in favor of the Enterprise edition. Long-term support starts December 10, 2025. End-of-life is December 31, 2026.
- Enterprise - Available as cloud-hosted or self-hosted. Requires Unleash Enterprise v7.3+.

## Beta features

Some new Unleash features are tagged as `BETA` in the documentation. This means that the feature may be subject to change or discontinuation. Unleash may decide to enable such features for a select number of customers only. If you're interested in trying out a beta feature, please reach out to Customer Success at beta@getunleash.io.

## Versioning

Unleash versions use the format `MAJOR.MINOR.BUILD`. Builds can include new features and other changes as well as fixes. Unleash Open Source and Unleash Enterprise share major and minor versions, but their builds are numbered independently. For what each part of the version means, where to find each build, and what to expect when you upgrade, see [Versioning](/release-notes) in the release notes overview.

If you are using Unleash Cloud, your instance is automatically on the latest Unleash Enterprise build. Unleash Cloud is a hosted service with continuous delivery. For transparency, we append build metadata to the base version for every deployment. For example, in `8.3.3+27802.9fe5f69d41`, `8.3.3` is the base release and `+27802.9fe5f69d41` identifies the exact build.

If you're self-hosting Unleash, see [Upgrading Unleash](/deploy/upgrading-unleash) for how to keep your instance up to date.

[Unleash Edge](https://github.com/Unleash/unleash-edge) and our [SDKs](/sdks) are versioned and released independently of Unleash. We recommend upgrading your SDKs and Unleash Edge to the latest versions to ensure compatibility, optimal performance, and access to the latest features and security updates.

In cases where a feature requires both a minimum Unleash version and a minimum Unleash Edge version, the requirements are specified as follows:

<Button small outlined className="version-button" href="/support/availability">v5.7</Button> <Button small outlined className="version-button" href="/support/availability">Edge v20.1</Button>

This indicates that the feature is available in Unleash version `5.7` or later and Unleash Edge version `20.1` or later.

### SDK versioning

Each [SDK](/sdks) follows semantic versioning and publishes its own release notes on GitHub. When a feature requires a minimum SDK version, the SDK documentation marks it with the following annotation:

<Button small outlined className="version-button" href="/support/availability#sdk-versioning">SDK v6.9.0+</Button>

This indicates that the feature is available in version `6.9.0` or later of that SDK. The version refers to the SDK, not to Unleash.

To see which features each backend SDK supports, see the [feature compatibility tables](/sdks#feature-compatibility-in-backend-sdks).

The App for Slack integration posts messages to a specified set of channels in your Slack workspace. The channels can be public or private, and can be specified on a per-flag basis by using [Slack tags](#tags).

## Installation

<Button small outlined className="version-button" href="/support/availability">v8.4</Button> <span data-badge-type="availability" title="Beta" class="fern-docs-badge large blue subtle rounded-full">Beta</span>

To install the App for Slack integration, follow these steps:

1. In the Unleash Admin UI, go to **Configure > Integrations**.
2. For the App for Slack integration, click **Configure**.
3. Click **Install & connect**.
4. On the **Connect Slack to this Unleash?** page, check that the address shown is the address of your Unleash instance, and then click **Continue to Slack**.
5. If Slack prompts you to sign in, sign in to your Slack workspace.
6. In the **Where do you want to use Unleash Feature Flags?** list, select the workspace where you want to install the app, and then click **Allow**. Slack redirects you back to Unleash, which saves the integration with its access token and opens it for editing.
7. In the **Events** list, select the [events](#events) that you want to be notified about.
8. Optional: In the **Channels** field, enter a comma-separated list of [channels](#parameters) to post the events to.
9. Click **Update**.

By default, the Unleash App for Slack is granted access to public channels. If you want the app to post messages to private channels, you'll need to manually invite it to each of those channels.

<Accordion title="Legacy installation">

If you use an Unleash version earlier than v8.4, or **Install & connect** opens a new tab that shows an access token after you install the app, your Unleash instance uses the legacy installation flow. To install the app by copying the access token to Unleash manually, follow these steps:

1. In the Unleash Admin UI, go to **Configure > Integrations**.
2. For the App for Slack integration, click **Configure**.
3. Click **Install & connect**. Slack opens in a new tab.
4. If Slack prompts you to sign in, sign in to your Slack workspace.
5. Select the workspace where you want to install the app, and then click **Allow**. Slack redirects you to a page that shows your access token.
6. Copy the access token.
7. In Unleash, in the **Access token** field of the integration form, paste the access token.
8. In the **Events** list, select the [events](#events) that you want to be notified about.
9. Optional: In the **Channels** field, enter a comma-separated list of [channels](#parameters) to post the events to.
10. Click **Create**.

</Accordion>

## Configuration

The configuration settings allow you to choose the events you're interested in and whether you want to filter them by projects and environments. You can configure a comma-separated list of channels to post the configured events to. These channels are always notified, regardless of the event type or the presence of [Slack tags](#tags).

#### Parameters

The Unleash App for Slack integration takes the following parameters.

- **Access token** - This is the only required property. Unleash sets it automatically when Slack redirects you back after installation. In the legacy installation flow, you copy the access token manually. See [Installation](#installation).
- **Channels** - A comma-separated list of channels to post the configured events to. These channels are always notified, regardless of the event type or the presence of a Slack tag.

## Tags

Besides the configured channels, you can choose to notify other channels by tagging your feature flags with Slack-specific tags. For instance, if you want the Unleash App for Slack to send notifications to the `#general` channel, add a Slack-type tag with the value "general" (or "#general"; both will work) to your flag. This will ensure that any configured events related to that feature flag will notify the tagged channel in addition to any channels configured on the integration-level.

To exclusively use tags for determining notification channels, you can leave the "channels" field blank in the integration configuration. Since you can have multiple configurations for the integration, you're free to mix and match settings to meet your precise needs. Before posting a message, all channels for that event, both configured and tagged, are combined and duplicates are removed.

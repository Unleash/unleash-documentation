## Initialization

<Markdown src="/snippets/sdks/backend-singleton-warning.mdx" />

<Markdown src="/snippets/sdks/backend-connection.mdx" />

```js
import { initialize } from 'unleash-client';

const unleash = initialize({
  url: 'https://<your-unleash-instance>/api/',
  appName: 'my-node-name',
  customHeaders: { Authorization: '<your-backend-token>' },
});
```

The `initialize` function configures a **global** Unleash instance. If a global instance already exists with the same configuration, `initialize` returns it. If the configuration differs, it throws an error. Call `destroy` to remove the global instance before reinitializing with a different configuration.

### Construct the client directly

You can construct a client instance yourself instead of using the global `initialize` function. When using the constructor, attach an error listener to surface errors, since they are not logged automatically.

```js
import { Unleash } from 'unleash-client';

const unleash = new Unleash({
  url: 'https://<your-unleash-instance>/api/',
  appName: 'my-node-name',
  customHeaders: { Authorization: '<your-backend-token>' },
});

unleash.on('error', console.error);
```

### Configure an HTTP proxy

The SDK uses the standard HTTP proxy environment variables.

Set `HTTPS_PROXY` or `HTTP_PROXY` in the environment where your service runs:

```bash
export HTTPS_PROXY=http://proxy.internal:8080
export NO_PROXY=localhost,127.0.0.1,.internal
```

### Check if the SDK is ready

Until the SDK has synchronized with Unleash, all flags evaluate to `false` and variants resolve to the [disabled variant](/concepts/feature-flag-variants#the-disabled-variant), unless you have a [bootstrapped configuration](#bootstrap).

Listen for the `synchronized` event to know when the SDK has fresh data from the Unleash API:

```js
unleash.on('synchronized', () => {
  // the SDK has synchronized with the server
  // and is ready to serve
});
```

Alternatively, use the `startUnleash` function to `await` synchronization:

```js
import { startUnleash } from 'unleash-client';

const unleash = await startUnleash({
  url: 'https://<your-unleash-instance>/api/',
  appName: 'my-node-name',
  customHeaders: { Authorization: '<your-backend-token>' },
});

// The SDK has a fresh state from the Unleash API
const isEnabled = unleash.isEnabled('my-feature');
```

## Configuration options

Pass these options to `initialize`, `startUnleash`, or the `Unleash` constructor.

<ParamField path="url" type="string" required={true}>
  Base URL to your Unleash or Edge API, for example: `https://<your-unleash-instance>/api/`.
</ParamField>

<ParamField path="appName" type="string" required={true}>
  Name of your application. Included in registration, metrics, and request headers.
</ParamField>

<ParamField path="customHeaders" type="Record<string, string>">
  Custom headers for all API requests. Use this to set the `Authorization` header with your backend token.
</ParamField>

<ParamField path="customHeadersFunction" type="() => Promise<Record<string, string>>">
  Async function that returns custom headers. When set, takes precedence over `customHeaders`.
</ParamField>

<ParamField path="environment" type="string" default="default">
  Environment value included in the Unleash context. This does **not** set the SDK's [Unleash environment](/concepts/environments).
</ParamField>

<ParamField path="instanceId" type="string">
  A unique identifier for this SDK instance. If omitted, the SDK generates one.
</ParamField>

<ParamField path="refreshInterval" type="number" default="15000">
  How often (in milliseconds) the SDK polls for updated flag configuration.
</ParamField>

<ParamField path="metricsInterval" type="number" default="60000">
  How often (in milliseconds) the SDK sends usage metrics to Unleash.
</ParamField>

<ParamField path="metricsJitter" type="number" default="0">
  Maximum jitter (in milliseconds) added to the metrics interval.
</ParamField>

<ParamField path="disableMetrics" type="boolean" default="false">
  Disables client registration and metrics posting when set to `true`.
</ParamField>

<ParamField path="strategies" type="Strategy[]">
  Custom activation strategies. See [custom strategies](#custom-strategies).
</ParamField>

<ParamField path="namePrefix" type="string">
  Only fetch feature flags whose names start with this prefix.
</ParamField>

<ParamField path="tags" type="Array<{name: string, value: string}>">
  Only fetch feature flags tagged with the provided tags, for example: `[{name: 'simple', value: 'proxy'}]`.
</ParamField>

<ParamField path="projectName" type="string">
  Restricts flag fetches to a single project. Prefer using a [project scoped API token](/concepts/api-tokens-and-client-keys#api-token-format) instead.
</ParamField>

<ParamField path="timeout" type="number" default="10000">
  Timeout in milliseconds for outgoing HTTP requests.
</ParamField>

<ParamField path="backupPath" type="string" default="os.tmpdir()">
  Directory used for persisting SDK state to disk.
</ParamField>

<ParamField path="repository" type="RepositoryInterface">
  Custom repository implementation to manage the underlying data layer. Your repository must emit a `ready` event after the client has been constructed. See the [custom repository example](https://github.com/Unleash/unleash-client-node/blob/main/examples/custom_repository.js).
</ParamField>

<ParamField path="storageProvider" type="StorageProvider">
  Custom storage provider for local persistence. See [local caching and offline behavior](#local-caching-and-offline-behavior).
</ParamField>

<ParamField path="bootstrap" type="BootstrapOptions">
  Bootstrap configuration for initial flag data. See [bootstrap](#bootstrap).
</ParamField>

<ParamField path="bootstrapOverride" type="boolean" default="true">
  When `true`, bootstrap data takes precedence over cached data. When `false`, cached data is preferred if available.
</ParamField>

<ParamField path="httpOptions" type="HttpOptions">
  Custom HTTP options such as `rejectUnauthorized` and a custom `agent` function. Use caution as these may affect application security.
</ParamField>

<ParamField path="disableAutoStart" type="boolean" default="false">
  When `true`, the SDK does not start polling or sending metrics until you manually call `start()`.
</ParamField>

<ParamField path="skipInstanceCountWarning" type="boolean" default="false">
  Suppresses the warning emitted when more than 10 SDK instances are created.
</ParamField>

<ParamField path="experimentalMode" type="Mode" default="{ type: 'polling', format: 'full' }">
  Experimental. Controls how the SDK receives flag updates. Set `{ type: 'polling', format: 'delta' }` to fetch only changes instead of the full configuration, or `{ type: 'streaming' }` to receive updates over server-sent events. Streaming requires a server that supports it, such as [Unleash Edge](/unleash-edge/configure#synchronization-and-polling) with streaming enabled. If the streaming connection degrades, the SDK falls back to polling and reconnects automatically.
</ParamField>

## Check flags

### Check if a flag is enabled

Use `isEnabled` to evaluate a flag:

```js
const enabled = unleash.isEnabled('my-feature');

if (enabled) {
  // new behavior
}
```

`isEnabled` accepts an optional context and fallback:

```js
unleash.isEnabled(name, context?, fallback?);
```

| Parameter | Type | Description |
|---|---|---|
| `name` | `string` | The feature flag name. |
| `context` | `Context` | Optional [Unleash context](#unleash-context) for this evaluation. |
| `fallback` | `boolean` or `(name, context) => boolean` | Value or function used when the flag cannot be resolved. Defaults to `false`. |

The fallback applies when the SDK cannot resolve the flag, for example, before initial synchronization or when the flag does not exist. Pass a boolean for a static default, or a function for per-call logic:

```js
const enabled = unleash.isEnabled('my-feature', { userId: '123' }, (name, ctx) => {
  return ctx.userId === 'admin';
});
```

### Check a flag's variant

Use `getVariant` to retrieve a flag's variant:

```js
const variant = unleash.getVariant('checkout-experiment');

if (variant.name === 'blue') {
  // blue variant behavior
} else if (variant.name === 'green') {
  // green variant behavior
}
```

`getVariant` accepts an optional context and fallback variant:

```js
unleash.getVariant(name, context?, fallbackVariant?);
```

| Parameter | Type | Description |
|---|---|---|
| `name` | `string` | The feature flag name. |
| `context` | `Context` | Optional [Unleash context](#unleash-context) for this evaluation. |
| `fallbackVariant` | `Variant` | Variant returned when no variant can be resolved. Defaults to the SDK's [disabled variant](/concepts/feature-flag-variants#the-disabled-variant). |

The SDK can return two forms of the disabled variant:

- Feature disabled or not found: `{ name: 'disabled', enabled: false, feature_enabled: false }`
- Feature enabled but no variant resolved (for example, no variants configured): `{ name: 'disabled', enabled: false, feature_enabled: true }`

In both cases, `name` is `'disabled'` and `enabled` is `false`. Use `feature_enabled` to distinguish the two. The returned object also includes a deprecated `featureEnabled` field for backwards compatibility. Prefer `feature_enabled` in new code.

Example with a fallback variant:

```js
const fallbackVariant = {
  name: 'fallback',
  enabled: true,
  payload: { type: 'string', value: 'default' },
};

const variant = unleash.getVariant('checkout-experiment', {}, fallbackVariant);

if (variant.enabled) {
  // use variant.name and variant.payload
}
```

## Unleash context

<Markdown src="/snippets/sdks/unleash-context-intro.mdx" />

Pass the context as the second argument to `isEnabled` or `getVariant`:

```js
const unleashContext = {
  userId: '123',
  sessionId: 'some-session-id',
  remoteAddress: '127.0.0.1',
  properties: {
    region: 'EMEA',
  },
};

const enabled = unleash.isEnabled('my-feature', unleashContext);
const variant = unleash.getVariant('checkout-experiment', unleashContext);
```

For stable gradual rollout and stickiness, include at least `userId` or `sessionId`.

## Stop the client

Call `destroyWithFlush` to send any pending metrics and then shut down the client, or `destroy` to shut down immediately. A destroyed client cannot be restarted.

```js
import { destroyWithFlush } from 'unleash-client';

await destroyWithFlush();
```

Both functions are also available as methods on the client instance. To send pending metrics without shutting down, call `flushMetrics`.

## Custom strategies

The SDK supports all [built-in activation strategies](/concepts/activation-strategies). To add a custom strategy, implement a `Strategy` subclass and pass it in the `strategies` option:

```js
import { initialize, Strategy } from 'unleash-client';

class ActiveForUserWithEmailStrategy extends Strategy {
  constructor() {
    super('ActiveForUserWithEmail');
  }

  isEnabled(parameters, context) {
    return parameters.emails.indexOf(context.email) !== -1;
  }
}

const unleash = initialize({
  url: 'https://<your-unleash-instance>/api/',
  appName: 'my-node-name',
  customHeaders: { Authorization: '<your-backend-token>' },
  strategies: [new ActiveForUserWithEmailStrategy()],
});
```

## Events

The Unleash client implements the EventEmitter interface and emits the following events:

| Event | Payload | Description |
|---|---|---|
| `ready` | - | The local cache is ready. The SDK may not have synchronized with the API yet. |
| `synchronized` | - | The SDK has successfully synchronized with the Unleash API or been bootstrapped. |
| `registered` | `object` data | The SDK has registered with the Unleash API. |
| `sent` | `object` data | Metrics payload was sent to Unleash. |
| `count` | `string` name, `boolean` enabled | A flag evaluation was counted for metrics. |
| `warn` | `string` msg | The SDK emitted a warning. |
| `error` | `Error` err | The SDK encountered an error. |
| `unchanged` | - | New flag state was fetched but nothing changed. |
| `changed` | `object` data | New flag state was fetched and changes were detected. |
| `impression` | `object` data | A flag was evaluated with [impression data](/concepts/impression-data) enabled. |

```js
import { initialize } from 'unleash-client';

const unleash = initialize({
  appName: 'my-app-name',
  url: 'https://<your-unleash-instance>/api/',
  customHeaders: { Authorization: '<your-backend-token>' },
});

unleash.on('ready', console.log);
unleash.on('synchronized', console.log);
unleash.on('error', console.error);
unleash.on('warn', console.warn);

unleash.once('registered', () => {
  // The SDK has registered with the server API.
});

unleash.once('changed', () => {
  console.log(`my-feature is enabled: ${unleash.isEnabled('my-feature')}`);
});

unleash.on('count', (name, enabled) => console.log(`isEnabled(${name})`));
```

## Impact metrics

<span data-badge-type="availability" title="Beta" class="fern-docs-badge large blue subtle rounded-full">Beta</span>

<Markdown src="/snippets/sdks/impact-metrics.mdx" />

The SDK automatically attaches `appName` and `environment` labels to all impact metrics.

Initialize the SDK and publish impact metrics:

```js
import { initialize } from 'unleash-client';

const unleash = initialize({
  url: 'https://<your-unleash-instance>/api/',
  appName: 'my-node-name',
  environment: 'production',
  customHeaders: { Authorization: '<your-backend-token>' },
});

unleash.impactMetrics.defineCounter(
  'request_count',
  'Total number of HTTP requests processed',
);
unleash.impactMetrics.incrementCounter('request_count');

unleash.impactMetrics.defineGauge(
  'active_users',
  'Current number of active users',
);
unleash.impactMetrics.updateGauge('active_users', 42);

unleash.impactMetrics.defineHistogram(
  'request_time_ms',
  'Request processing time in milliseconds',
);
unleash.impactMetrics.observeHistogram('request_time_ms', 125);
```

### Metric types

<Tabs>
<Tab title="Counter">

Use counters for cumulative values that only increase, such as the total number of requests or errors.

```js
unleash.impactMetrics.defineCounter(
  'request_count',
  'Total number of HTTP requests processed',
);
unleash.impactMetrics.incrementCounter('request_count');
```

</Tab>
<Tab title="Gauge">

Use gauges for values that can go up or down, such as current memory usage or active user count.

```js
unleash.impactMetrics.defineGauge(
  'active_users',
  'Current number of active users',
);
unleash.impactMetrics.updateGauge('active_users', 42);
```

</Tab>
<Tab title="Histogram">

Histograms measure distributions such as latency and payload size. `defineHistogram` accepts an optional third argument with custom bucket boundaries.

```js
unleash.impactMetrics.defineHistogram(
  'request_time_ms',
  'Request processing time in milliseconds',
  [10, 50, 100, 250, 500, 1000],
);
unleash.impactMetrics.observeHistogram('request_time_ms', 125);
```

</Tab>
</Tabs>

Impact metrics are batched and sent on the same interval as standard SDK metrics (`metricsInterval`).

## Bootstrap

You can bootstrap the SDK with flag configuration to evaluate flags without waiting for the Unleash API. Provide the bootstrap as inline `data`, a `url` to fetch from, or a `filePath` to load.

<Tabs>
<Tab title="Inline data">

```js
const unleash = initialize({
  appName: 'my-application',
  url: 'https://<your-unleash-instance>/api/',
  customHeaders: { Authorization: '<your-backend-token>' },
  bootstrap: {
    data: [
      {
        enabled: false,
        name: 'BootstrapDemo',
        description: '',
        project: 'default',
        stale: false,
        type: 'release',
        variants: [],
        strategies: [{ name: 'default' }],
      },
    ],
  },
});
```

</Tab>

```js
const unleash = initialize({

  customHeaders: { Authorization: '<your-backend-token>' },

    url: 'http://localhost:3000/proxy/client/features',

      Authorization: 'bootstrap',

});
```

## Local caching and offline behavior

By default, the SDK writes a backup of the flag configuration to a file on disk each time it receives an update from the Unleash API. On startup, the SDK loads cached state first, then fetches fresh data.

If Unleash is temporarily unreachable:

- The SDK continues serving cached or bootstrapped values.
- Polling continues on `refreshInterval`.
- Flag evaluations return `false` when no data exists.

### Custom storage providers

Swap the default file-backed storage with the built-in in-memory provider or your own implementation:

```js
import { initialize, InMemStorageProvider } from 'unleash-client';

const unleash = initialize({
  appName: 'my-application',
  url: 'https://<your-unleash-instance>/api/',
  customHeaders: { Authorization: '<your-backend-token>' },
  storageProvider: new InMemStorageProvider(),
});
```

A custom provider must implement `set(key, data)` and `get(key)` methods. For example, a Redis-backed store:

```js
import { createClient } from 'redis';

class RedisStorageProvider {
  async set(key, data) {
    const client = createClient();
    await client.connect();
    await client.set(key, JSON.stringify(data));
  }
  async get(key) {
    const client = createClient();
    await client.connect();
    const data = await client.get(key);
    return JSON.parse(data);
  }
}

const unleash = initialize({
  appName: 'my-application',
  url: 'https://<your-unleash-instance>/api/',
  customHeaders: { Authorization: '<your-backend-token>' },
  storageProvider: new RedisStorageProvider(),
});
```

## Flag definitions

Sometimes you might be interested in the raw feature flag definitions.

```js
import {
  initialize,
  getFeatureToggleDefinition,
  getFeatureToggleDefinitions,
} from 'unleash-client';

initialize({
  url: 'https://<your-unleash-instance>/api/',
  customHeaders: { Authorization: '<your-backend-token>' },
  appName: 'my-app-name',
  instanceId: 'my-unique-instance-id',
});

const featureToggleX = getFeatureToggleDefinition('app.ToggleX');
const featureToggles = getFeatureToggleDefinitions();
```

Pass `true` to `getFeatureToggleDefinitions` to include full segment data on each strategy:

```js
const featureTogglesWithSegments = getFeatureToggleDefinitions(true);
```

## TypeScript: custom feature flag names

You can use TypeScript module augmentation to provide type safety for your feature flag names. This catches flag name typos at compile time.

```typescript
import { initialize } from 'unleash-client';

declare module 'unleash-client' {
  interface UnleashTypes {
    flagNames: 'my-feature' | 'checkout-experiment';
  }
}

const unleash = initialize({
  url: 'https://<your-unleash-instance>/api/',
  appName: 'my-node-name',
  customHeaders: { Authorization: '<your-backend-token>' },
});

unleash.isEnabled('my-feature'); // OK
unleash.isEnabled('checkout-experiment'); // OK
unleash.isEnabled('typo-flag'); // Compile error
```

## Unit testing

For unit tests, construct a scoped `Unleash` instance with bootstrapped flag data, disabled metrics, and in-memory storage. This gives deterministic flag state without depending on a real Unleash instance.

Use the `Unleash` constructor instead of `initialize` so each test gets its own client rather than sharing the global singleton.

```js
import { Unleash, InMemStorageProvider } from 'unleash-client';

function createTestClient() {
  const unleash = new Unleash({
    appName: 'test-app',
    url: 'http://unleash.test/api/',
    disableMetrics: true,
    refreshInterval: 24 * 60 * 60 * 1000,
    storageProvider: new InMemStorageProvider(),
    bootstrap: {
      data: [
        {
          name: 'my-feature',
          enabled: true,
          strategies: [{ name: 'default' }],
        },
      ],
    },
  });

  unleash.on('error', () => {}); // suppress network errors during tests
  return unleash;
}

test('my-feature is enabled', async () => {
  const unleash = createTestClient();
  await new Promise((resolve) => unleash.on('synchronized', resolve));

  expect(unleash.isEnabled('my-feature')).toBe(true);

  unleash.destroy();
});
```

Mock HTTP requests with [nock](https://github.com/nock/nock) to fully isolate tests from the network.

## Migrating to v6

When upgrading from v5:

- The SDK generates `instanceId` automatically. You no longer need to set it, but you can still provide your own value to identify an instance.
- The minimum supported Node.js version is 20 as of v6.9. Earlier v6 releases support Node.js 16 or later.

## Troubleshooting

<AccordionGroup>
<Accordion title="SDK does not become ready">

If `startUnleash` hangs or the `synchronized` event never fires:

- Verify `url` points to your Unleash API base URL (for example, `https://<your-instance>/api/`).
- Verify `customHeaders` includes a valid backend API token in `Authorization`.
- Confirm network connectivity from your service to the Unleash instance.
- Listen for `error` events to inspect failures: `unleash.on('error', console.error)`.

</Accordion>
<Accordion title="All flags evaluate to false">

If `isEnabled` always returns `false`:

- Confirm the flag exists (check for typos).
- Confirm the flag is enabled in the target environment.
- Verify your [Unleash context](/concepts/unleash-context) fields match your rollout strategy and constraints.
- Verify the SDK completed initial sync (`synchronized` event fired or `startUnleash` resolved).

</Accordion>
</AccordionGroup>

The [Unleash MCP server](/integrate/mcp) connects Kiro to your Unleash instance, enabling AI-assisted feature flag management.
This page covers how to install and configure the server in Kiro. To learn what the server can do, see [Unleash MCP server](/integrate/mcp).

Kiro supports MCP across two interfaces:

- **Kiro IDE** — The primary interface, built on Code OSS
- **Kiro CLI** — Interactive terminal-based chat (successor to Amazon Q Developer CLI)

## Prerequisites

Before you begin, make sure you have the following:

- Node.js 24 or later: The MCP server is distributed as an npm package
- Kiro: [IDE or CLI](https://kiro.dev/) installed
- An Unleash instance: Cloud or self-hosted, with API access enabled
- A [personal access token](/concepts/api-tokens-and-client-keys#personal-access-tokens) (PAT): With permissions to create and manage feature flags

## Install the MCP server

The Unleash MCP server runs as a local stdio process. Configuration differs between the IDE and CLI, but both use the same npm package and credentials.

Kiro uses `${VAR}` expansion for environment variables. Create a credentials file and source it from your shell profile:

<Steps>

<Step title="Create credentials file">
```bash
mkdir -p ~/.unleash
cat > ~/.unleash/mcp.env << 'EOF'
UNLEASH_BASE_URL=https://your-instance.getunleash.io
UNLEASH_PAT=your-personal-access-token
EOF
chmod 600 ~/.unleash/mcp.env
```
</Step>

<Step title="Source in shell profile">
Add to your `~/.zshrc` or `~/.bashrc`:

```bash
if [ -f ~/.unleash/mcp.env ]; then
  source ~/.unleash/mcp.env
  export UNLEASH_BASE_URL UNLEASH_PAT
fi
```
</Step>

<Step title="Reload your shell">
```bash
source ~/.zshrc  # or ~/.bashrc
```
</Step>

</Steps>

| Variable | Description | Required |
|----------|-------------|----------|
| `UNLEASH_BASE_URL` | Your Unleash instance API URL. | Yes |
| `UNLEASH_PAT` | A personal access token with flag creation permissions. | Yes |
| `UNLEASH_MCP_SEND_FEEDBACK` | Set to `true` or `false` to opt in to or out of [feedback reports](/integrate/mcp#send-feedback) without a consent prompt. With `false`, the assistant doesn't see the `send_feedback` tool. | No |

Now configure your preferred interface:

<Tab title="Kiro IDE">

**Enable MCP support (one-time step):**

1. Open Settings (`Cmd+,` on macOS, `Ctrl+,` on Windows/Linux)
2. Search for **MCP**
3. Enable the **Kiro: MCP** setting

### Configure `autoApprove` and `disabledTools`

Kiro supports two MCP configuration properties for controlling tool approval:

| Property | Type | Description |
|----------|------|-------------|
| `autoApprove` | Array of strings | Tool names that Kiro can invoke without asking for confirmation. Use `"*"` for all tools. |
| `disabledTools` | Array of strings | Tool names to hide from the agent entirely. |

Example with auto-approval for read-only tools:

```json title=".kiro/settings/mcp.json" {10}
{
  "mcpServers": {
    "unleash": {
      "command": "npx",
      "args": ["-y", "@unleash/mcp@latest"],
      "env": {
        "UNLEASH_BASE_URL": "${UNLEASH_BASE_URL}",
        "UNLEASH_PAT": "${UNLEASH_PAT}"
      },
      "autoApprove": ["search", "inspect", "evaluate", "audit", "docs"]
    }
  }
}
```

<Tip>
Use `autoApprove` for the read-only tools: `search`, `inspect`, `evaluate`, `audit`, and `docs`.
Keep write operations such as `release`, `kill_switch`, `experiment`, `manage_flag`, and `configure` behind manual approval.

To turn off [feedback reports](/integrate/mcp#send-feedback), set `UNLEASH_MCP_SEND_FEEDBACK` to `"false"` in the `env` block. You can also add `send_feedback` to `disabledTools`.
</Tip>

**Configuration scopes:**

| Location | Scope | Use case |
|----------|-------|----------|
| `.kiro/settings/mcp.json` (project) | Workspace | Team-shared, version controlled |
| `~/.kiro/settings/mcp.json` | User | Personal settings across all projects |

Both are merged; workspace takes precedence on conflict. For team collaboration, use the workspace-level file.

</Tab>

## Tools and workflows

Once the server is connected, Kiro can use every tool the Unleash MCP server exposes. To learn what the server can do and see step-by-step [workflows](/integrate/mcp#workflows), read [Unleash MCP server](/integrate/mcp). For the current list of tools, see the [README on GitHub](https://github.com/Unleash/unleash-mcp#tools).

### Feedback reports

The first time the assistant tries to send a [feedback report](/integrate/mcp#send-feedback), Kiro shows a consent prompt in the execution timeline. The MCP server saves whether you opted in or out, so you see the prompt only once.

To opt in or out without the prompt, set `UNLEASH_MCP_SEND_FEEDBACK` to `"true"` or `"false"` in the `env` block of `.kiro/settings/mcp.json`. With `"false"`, the assistant doesn't see the `send_feedback` tool, so you don't need to add it to `disabledTools`. To learn what a report contains, see [What is recorded](/integrate/mcp#what-is-recorded).

## Unleash Power

A [Power](https://kiro.dev/docs/powers/) bundles MCP tools, steering files, and hook definitions into a single installable package. The Unleash Power is the recommended way to distribute the integration across teams and projects. It is published as a public repository at [github.com/Unleash/unleash-kiro-power](https://github.com/Unleash/unleash-kiro-power), which documents what the Power contains.

### Install the Power

You can install the Unleash Power from GitHub or from a local copy of the repository:

- **From GitHub:** Open the Powers panel, select "Add power from GitHub," and enter the repository URL `https://github.com/Unleash/unleash-kiro-power`. If your team forked the repo to customize it, use your fork's URL instead.
- **From local path:** Clone the repository, open the Powers panel, select "Add power from Local Path," and choose the cloned directory.

When installed, the Power's MCP server is auto-registered in `~/.kiro/settings/mcp.json` under the "Powers" section with a namespaced server name (e.g., `power-unleash-unleash`).

For more details on creating and distributing Powers, see the [Kiro Powers documentation](https://kiro.dev/docs/powers/).

## Enterprise governance

Kiro provides enterprise controls through AWS IAM Identity Center (which can federate to external identity providers such as Okta and Microsoft Entra ID).

- **Extension registry governance** — Point the IDE at a curated extension registry to control which extensions are available
- **Web tools toggle** — Enable or disable web search and fetch per organization policy
- **Supervised mode enforcement** — Require supervised mode for all users, preventing autonomous agent actions
- **Trusted commands list** — Define which shell commands the agent can execute

For MCP server governance, commit `.kiro/settings/mcp.json` to version control. This ensures all team members use the same MCP servers with the same settings.

<Tip>
Use Supervised mode for flag operations that change an environment, such as releases and kill switches.
Autopilot mode works well for read-only operations like searching and inspecting flags.
</Tip>

## Troubleshooting

<Accordion title="MCP server not appearing in Kiro">
- Check `.kiro/settings/mcp.json` for syntax errors
- Verify the file is in the correct location (workspace root under `.kiro/settings/`)
- Restart Kiro after making changes
- Right-click the server in the MCP Servers tab and select **Show MCP Logs**
</Accordion>

<Accordion title="Unapproved environment variables">
If you see "Found unapproved environment variables in MCP config," Kiro requires explicit approval before expanding variables.

- When you first save the config, click **Allow** on the popup to approve the listed variables
- Or open Settings, search for **Mcp Approved Env Vars**, and add `UNLEASH_BASE_URL` and `UNLEASH_PAT`
- After approving, restart Kiro or reload the window
</Accordion>

<Accordion title="Environment variables not expanding">
- Restart your terminal or IDE after modifying your shell profile
- Run `source ~/.zshrc` to reload
- Kiro inherits environment variables from the shell that launched it
- Verify variables are exported: `echo $UNLEASH_BASE_URL`
- Verify the variables are approved in Settings → **Mcp Approved Env Vars**
</Accordion>

<Accordion title="Authentication failed">
- Confirm your Unleash PAT is valid and has not expired
- Check that the PAT has permissions to create and manage feature flags
- Verify that `UNLEASH_BASE_URL` does not include `/api` at the end
- Test directly: `curl -H "Authorization: $UNLEASH_PAT" "$UNLEASH_BASE_URL/api/admin/projects"`
</Accordion>

<Accordion title="Power not activating">
- Check that keywords in the `POWER.md` frontmatter match what you are saying in chat
- Powers activate on keyword matches — use terms like "feature flag," "rollout," or "unleash"
- Verify the Power is installed in the Powers panel
</Accordion>

<Accordion title="autoApprove not working">
- The `autoApprove` array must use exact tool names
- Use `"*"` to approve all tools, or list specific names like `["search", "inspect"]`
- Verify the property is inside the server configuration object, not at the root level
</Accordion>

<Accordion title="Workspace vs user config conflict">
Workspace configuration (`.kiro/settings/mcp.json`) takes precedence over user configuration (`~/.kiro/settings/mcp.json`). If a server is disabled in workspace config, it remains disabled even if enabled in user config.
</Accordion>

<Accordion title="Feedback is disabled">
`send_feedback` returns this message if you declined the consent prompt, if Kiro couldn't show it, or if `UNLEASH_MCP_SEND_FEEDBACK` is set to `false`. To opt in, set `UNLEASH_MCP_SEND_FEEDBACK` to `"true"` in the `env` block of `.kiro/settings/mcp.json`, approve the variable when Kiro asks, and reconnect the server. To see the consent prompt again, delete `feedback_consent.json` from the [configuration directory](/integrate/mcp#consent). Feedback settings don't affect flag operations.
</Accordion>

The [Unleash MCP server](/integrate/mcp) connects [Claude Code](https://claude.com/product/claude-code) to your Unleash instance, enabling AI-assisted feature flag management. This page covers how to install and configure the server in Claude Code. To learn what the server can do, see [Unleash MCP server](/integrate/mcp).

Claude Code supports MCP across multiple interfaces:

- **Terminal CLI** — The primary interface, built for developers who live in the terminal.
- **VS Code** — Extension for Visual Studio Code.
- **JetBrains IDEs** — Plugin for IntelliJ IDEA, PyCharm, WebStorm, and others.
- **Desktop app** — Standalone application.
- **GitHub Actions** — CI/CD automation with `@anthropics/claude-code-action`.

## Prerequisites

Before you begin, make sure you have the following:

- Node.js 24 or later: the MCP server is distributed as an npm package.
- Claude Code, installed via your preferred method (see installation tabs).
- An Unleash instance: cloud or self-hosted, with API access enabled.
- A [personal access token](/concepts/api-tokens-and-client-keys#personal-access-tokens) (PAT) with permissions to create and manage feature flags.

## Install the MCP server

The Unleash MCP server runs as a local stdio process. Configuration differs by interface, but all use the same npm package and credentials.

Claude Code uses environment variable expansion, and we recommend creating a credentials file and source it from your shell profile:

<Steps>
<Step title="Create credentials file">
```bash
mkdir -p ~/.unleash
cat > ~/.unleash/mcp.env << 'EOF'
UNLEASH_BASE_URL=https://your-instance.getunleash.io
UNLEASH_PAT=your-personal-access-token
EOF
chmod 600 ~/.unleash/mcp.env
```
</Step>

<Step title="Source in shell profile">
Add to your `~/.zshrc` or `~/.bashrc`:

```bash
if [ -f ~/.unleash/mcp.env ]; then
  source ~/.unleash/mcp.env
  export UNLEASH_BASE_URL UNLEASH_PAT
fi
```
</Step>

<Step title="Reload your shell">
```bash
source ~/.zshrc  # or ~/.bashrc
```
</Step>
</Steps>

| Variable | Description | Required |
|----------|-------------|----------|
| `UNLEASH_BASE_URL` | Your Unleash instance API URL. | Yes |
| `UNLEASH_PAT` | A personal access token with flag creation permissions. | Yes |
| `UNLEASH_MCP_SEND_FEEDBACK` | Set to `true` or `false` to opt in to or out of [feedback reports](/integrate/mcp#send-feedback) without a consent prompt. With `false`, the assistant doesn't see the `send_feedback` tool. | No |

### Configure your interface

<Tabs>
<Tab title="Terminal CLI">

**Requirements:** [Claude Code CLI](https://github.com/anthropics/claude-code) installed.

The terminal CLI is Claude Code's native interface. Use the `claude mcp add` command to register the Unleash MCP server.

<Steps>
<Step title="Install Claude Code">

Choose your preferred [installation method](https://github.com/anthropics/claude-code?tab=readme-ov-file#get-started).

</Step>

<Step title="Add the Unleash MCP server">

You can either run the `claude mcp add` command or create the `.mcp.json` file manually.

Both approaches create the same `.mcp.json` file at your project root. Choose whichever you prefer.

<Tabs>
<Tab title="CLI command">
Run the following command from your project directory:

```bash
claude mcp add --transport stdio --scope project unleash \
  -e UNLEASH_BASE_URL='${UNLEASH_BASE_URL}' \
     UNLEASH_PAT='${UNLEASH_PAT}' \
  -- npx -y @unleash/mcp@latest
```

**Syntax notes:**
- The server name (`unleash`) comes before the `-e` flag
- Multiple environment variables are space-separated after a single `-e`
- Single quotes around `${VAR}` preserve the literal string for runtime expansion
</Tab>

<Tab title="Create file manually">
Create a `.mcp.json` file at your project root:

```json title=".mcp.json"
{
  "mcpServers": {
    "unleash": {
      "command": "npx",
      "args": ["-y", "@unleash/mcp@latest"],
      "env": {
        "UNLEASH_BASE_URL": "${UNLEASH_BASE_URL}",
        "UNLEASH_PAT": "${UNLEASH_PAT}"
      }
    }
  }
}
```
</Tab>
</Tabs>

The resulting `.mcp.json` file can be committed to version control since it contains no credentials, only variable references that expand at runtime.

</Step>

<Step title="Verify the installation">
```bash
claude mcp get unleash
```

You should see output confirming the server configuration:

```
Name: unleash
Type: stdio
Command: npx -y @unleash/mcp@latest
Scope: Project config (shared via .mcp.json)
```

Within a Claude Code session, you can also run `/mcp` to see connected servers and available tools.
</Step>
</Steps>

**Installation scopes:**

| Scope | Storage | Use case |
|-------|---------|----------|
| **Local** (default) | `~/.claude.json` | Personal, single-project configs |
| **Project** | `.mcp.json` in project root | Team-shared, version controlled |
| **User** | `~/.claude.json` | Available across all projects |

For team collaboration, use `--scope project` so the configuration is stored in `.mcp.json` and can be committed to version control.

</Tab>

<Tab title="VS Code">

**Requirements:** VS Code with Claude Code extension installed.

<Steps>
<Step title="Install the Claude Code extension">
Install the Claude Code extension from the VS Code Marketplace or via the Extensions view (`Cmd+Shift+X`).
</Step>

<Step title="Create the configuration file">
If you have already configured the MCP server via the terminal CLI with `--scope project`, the `.mcp.json` file is automatically used by the VS Code extension.

Alternatively, create `.mcp.json` manually at your project root:

```json title=".mcp.json"
{
  "mcpServers": {
    "unleash": {
      "command": "npx",
      "args": ["-y", "@unleash/mcp@latest"],
      "env": {
        "UNLEASH_BASE_URL": "${UNLEASH_BASE_URL}",
        "UNLEASH_PAT": "${UNLEASH_PAT}"
      }
    }
  }
}
```
</Step>

<Step title="Reload VS Code">
After saving the file, reload VS Code by running **Developer: Reload Window** from the Command Palette. The MCP server starts automatically.
</Step>

<Step title="Verify the installation">
Open the Claude Code panel and run `/mcp` to see connected servers and available tools.
</Step>
</Steps>

<Note>
Note: The Claude Code VS Code extension uses `.mcp.json` at the project root (not `.vscode/mcp.json`) and the root key is `"mcpServers"` rather than `"servers"`.
</Note>

</Tab>

<Tab title="JetBrains IDEs">

**Requirements:** IntelliJ IDEA, PyCharm, WebStorm, or another JetBrains IDE with the Claude Code plugin or AI Assistant with MCP support.

<Steps>
<Step title="Go to AI Assistant settings">
Go to **Settings > Tools > AI Assistant  > Model Context Protocol (MCP)**.
</Step>

<Step title="Add the Unleash MCP server">
Click **Add** and provide the following JSON configuration:

```json
{
  "mcpServers": {
    "unleash": {
      "command": "npx",
      "args": ["-y", "@unleash/mcp@latest"]
    }
  }
}
```

Set environment variables (`UNLEASH_BASE_URL`, `UNLEASH_PAT`) in your system environment or working directory. JetBrains does not support `envFile` or variable expansion in the configuration.
</Step>

<Step title="Choose scope and enable">
Select **Global** or **Project** level depending on your needs. Ensure the server is enabled and restart the IDE if prompted.
</Step>
</Steps>

For detailed instructions, see the [JetBrains AI Assistant MCP documentation](https://www.jetbrains.com/help/ai-assistant/mcp.html).

</Tab>

<Tab title="Desktop App">

**Requirements:** Claude Desktop application installed.

The [Claude Desktop app](https://claude.com/download) provides a native interface for configuring MCP servers through its settings.

<Steps>
<Step title="Open MCP settings">
Open **Settings > Developer > Edit Config**. This opens the `claude_desktop_config.json` file.
</Step>

<Step title="Add the Unleash MCP server">
Add the Unleash server to the `mcpServers` object:

```json title="claude_desktop_config.json"
{
  "mcpServers": {
    "unleash": {
      "command": "npx",
      "args": ["-y", "@unleash/mcp@latest"],
      "env": {
        "UNLEASH_BASE_URL": "https://your-instance.getunleash.io",
        "UNLEASH_PAT": "your-personal-access-token"
      }
    }
  }
}
```

<Warning>
Unlike project-scoped configurations, the desktop app config does not support `${VAR}` environment variable expansion. Enter your credentials directly in the file, or use the Terminal CLI for project-scoped setup with variable expansion.
</Warning>
</Step>

<Step title="Restart and verify">
Save the file and restart Claude Desktop. The MCP server starts automatically. You can verify by asking Claude to list available Unleash tools.
</Step>
</Steps>

**Config file locations:**

| Platform | Path |
|----------|------|
| macOS | `~/Library/Application Support/Claude/claude_desktop_config.json` |
| Windows | `%APPDATA%\Claude\claude_desktop_config.json` |
| Linux | `~/.config/Claude/claude_desktop_config.json` |

</Tab>

<Tab title="GitHub Actions">

**Requirements:** GitHub repository with Actions enabled, Anthropic API key stored as a secret.

Use `@anthropics/claude-code-action` to run Claude Code in CI/CD pipelines. For MCP servers that require secrets, create a config file step.

<Steps>
<Step title="Add secrets to your repository">
Go to **Settings > Secrets and variables > Actions** and add:
- `ANTHROPIC_API_KEY`
- `UNLEASH_BASE_URL`
- `UNLEASH_PAT`
</Step>

<Step title="Create workflow file">
```yaml title=".github/workflows/feature-flag-review.yml"
name: Feature Flag Review

on:
  pull_request:
    types: [opened, synchronize]

jobs:
  flag-review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Create MCP Config
        run: |
          cat > /tmp/mcp-config.json << 'EOF'
          {
            "mcpServers": {
              "unleash": {
                "command": "npx",
                "args": ["-y", "@unleash/mcp@latest"],
                "env": {
                  "UNLEASH_BASE_URL": "${{ secrets.UNLEASH_BASE_URL }}",
                  "UNLEASH_PAT": "${{ secrets.UNLEASH_PAT }}"
                }
              }
            }
          }
          EOF

      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          claude_args: |
            --mcp-config /tmp/mcp-config.json
            --allowedTools mcp__unleash__search,mcp__unleash__inspect,mcp__unleash__evaluate
          prompt: "Review this PR and check whether any flags it touches are stale or still enabled in production"
```
</Step>
</Steps>

**Headless mode for scripts:**

For fully non-interactive execution outside GitHub Actions, use the `--print` flag:

```bash
claude --print --allowedTools "mcp__unleash__*" \
  "Audit feature flags and report stale ones" > report.md

# JSON output for parsing
claude --print --output-format json \
  "List flags older than 90 days" > audit.json
```

</Tab>
</Tabs>

## Tools and workflows

Once the server is connected, Claude Code can use every tool the Unleash MCP server exposes. To learn what the server can do and see step-by-step [workflows](/integrate/mcp#workflows), read [Unleash MCP server](/integrate/mcp). For the current list of tools, see the [README on GitHub](https://github.com/Unleash/unleash-mcp#tools).

### Feedback reports

The first time the assistant tries to send a [feedback report](/integrate/mcp#send-feedback), Claude Code shows a consent prompt in your session. The MCP server saves whether you opted in or out, so you see the prompt only once.

To opt in or out without the prompt, pass `-e UNLEASH_MCP_SEND_FEEDBACK=true` or `-e UNLEASH_MCP_SEND_FEEDBACK=false` to `claude mcp add`, or add the variable to the `env` block of your `.mcp.json`. To learn what a report contains, see [What is recorded](/integrate/mcp#what-is-recorded).

## Enterprise governance

For enterprise deployments, IT administrators can deploy centralized MCP configuration using managed settings.

### Managed MCP configuration

Deploy `managed-mcp.json` to system directories to control which MCP servers are available:

| Platform | Path |
|----------|------|
| macOS | `/Library/Application Support/ClaudeCode/managed-mcp.json` |
| Linux/WSL | `/etc/claude-code/managed-mcp.json` |
| Windows | `C:\Program Files\ClaudeCode\managed-mcp.json` |

When this file is present, users cannot add, modify, or use any MCP servers other than those defined in the file.

To opt your whole organization in to or out of [feedback reports](/integrate/mcp#send-feedback), set `UNLEASH_MCP_SEND_FEEDBACK` to `true` or `false` in the `env` block of the Unleash server in `managed-mcp.json`. With `false`, developers don't see a consent prompt and the assistant doesn't see the `send_feedback` tool.

### Policy-based control

Use `allowedMcpServers` and `deniedMcpServers` in managed settings to restrict which servers users can configure while still allowing some flexibility.

## Troubleshooting

<Accordion title="MCP tools not showing up">
- Verify the server is listed with `claude mcp list`
- Check that environment variables are exported: `echo $UNLEASH_BASE_URL`
- Test credentials directly: `curl -H "Authorization: $UNLEASH_PAT" "$UNLEASH_BASE_URL/api/admin/projects"`
- Restart your terminal after modifying your shell profile
</Accordion>

<Accordion title="Environment variables not expanding">
- Restart your terminal after modifying `~/.zshrc` or `~/.bashrc`
- Verify variables are exported: `export UNLEASH_BASE_URL UNLEASH_PAT`
- Check that single quotes were used in the `claude mcp add` command to prevent premature expansion
</Accordion>

<Accordion title="Authentication failed">
- Confirm your Unleash PAT is valid and has not expired
- Check that the PAT has permissions to create and manage feature flags
- Verify that `UNLEASH_BASE_URL` does not include `/api` at the end
- For self-hosted instances, ensure the API is accessible from your machine
</Accordion>

<Accordion title="Server crashes repeatedly">
Claude Code automatically restarts MCP servers that crash. If a server fails repeatedly, it will be disabled for the session. Check your credentials and restart Claude Code.
</Accordion>

<Accordion title="Node.js not found">
Local servers using npx require Node.js 24+. Verify with `node --version`. If Node.js is installed but not found, check your PATH.
</Accordion>

<Accordion title="Windows-specific issues">
On native Windows (not WSL), local MCP servers using `npx` require the `cmd /c` wrapper:

```bash
claude mcp add --transport stdio my-server -- cmd /c npx -y @unleash/mcp@latest
```

For WSL environments, use the standard Unix syntax.
</Accordion>

<Accordion title="Tool results truncated">
Claude Code limits tool output size to prevent context overflow. If results appear truncated, use filters (such as specific projects or flag types) to reduce result size. For current limits, see the [Claude Code MCP documentation](https://code.claude.com/docs/en/mcp).
</Accordion>

<Accordion title="Feedback is disabled">
`send_feedback` returns this message if you declined the consent prompt, if Claude Code couldn't show it, or if `UNLEASH_MCP_SEND_FEEDBACK` is set to `false`. To opt in, set `UNLEASH_MCP_SEND_FEEDBACK=true` in the `env` block of your `.mcp.json`, or pass it with `-e` to `claude mcp add`. To see the consent prompt again, delete `feedback_consent.json` from the [configuration directory](/integrate/mcp#consent). Feedback settings don't affect flag operations.
</Accordion>

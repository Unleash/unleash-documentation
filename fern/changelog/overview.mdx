This page provides a high-level summary of releases starting from 2025. It details new functionality, UI changes, deprecations, and important announcements across Unleash and its components.

<Accordion title="How to use the tags">
Each release note is tagged with the part of the product it applies to. Use the tags to filter for the areas you're interested in.

- **Unleash**: The core platform, including the Unleash server, the Admin UI, and overarching product decisions and announcements. See the [architecture overview](/get-started/unleash-overview).
- **Enterprise Edge**: Releases for [Unleash Enterprise Edge](/unleash-edge), a lightweight caching layer that improves the scalability, performance, and resilience of your feature flag infrastructure.
- **MCP server**: Releases for the [Unleash MCP server](/integrate/mcp), which lets AI coding assistants manage feature flags.
- **SDKs**: Changes that affect the [Unleash SDKs](/sdks), such as naming changes or new capabilities that span multiple SDKs.

A single release note can carry more than one tag when a release touches several areas.
</Accordion>

<Accordion title="Versioning">
Unleash versions use the format `MAJOR.MINOR.BUILD`:

- **Major versions** (for example, `v8.0.0`) introduce significant changes and can include breaking changes. Review the [upgrade guide](/deploy/upgrading-unleash) before you upgrade.
- **Minor versions** (for example, `v8.3.0`) are feature releases. This page summarizes each one.
- **Builds** (for example, `v8.3.1`) are published regularly between minor versions. They include dependency updates and security fixes, and can also include new features and other changes.

Unleash doesn't strictly follow semantic versioning. Builds come from the same code that runs Unleash Cloud and are designed to be backward compatible. In rare cases, a build includes a change that isn't backward compatible. When that happens:

- The release notes explain the change and typically include a migration or upgrade guide.
- Deprecated functionality remains available for a grace period before it's removed.
- Unleash contacts affected customers ahead of the change and works with them to plan the upgrade.

If you self-host Unleash, test new builds in a non-production environment before you upgrade.

[Unleash Open Source](/support/availability#plans) and Unleash Enterprise share major and minor versions, but their builds are numbered independently.
- **Unleash Open Source**: For a comprehensive list of releases, including builds and history prior to 2025, visit the [Unleash Releases](https://github.com/Unleash/unleash/releases) page on GitHub.
- **Unleash Enterprise**: Builds are published as [`unleashorg/unleash-enterprise` image tags](https://hub.docker.com/r/unleashorg/unleash-enterprise/tags) on Docker Hub. If you use Unleash Cloud, your instance is automatically on the latest build.

The [Unleash MCP server](/integrate/mcp), [Unleash Enterprise Edge](/unleash-edge), and each [SDK](/sdks) are versioned independently and publish their own changelog in their respective GitHub repositories.
</Accordion>
